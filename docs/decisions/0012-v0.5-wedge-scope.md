# 0012 — v0.5 ships as a single-surface, two-specialist, P&C-only wedge

**Status:** Proposed
**Date:** 2026-04-24

## Context

The accepted architecture (ADRs [0003](./0003-installable-via-aws-marketplace.md), [0006](./0006-v1-domain-anchor-insurance-claims.md), [0007](./0007-v1-cost-profile-and-llm-metering.md), [0011](./0011-canopy-and-ai-first-dmz.md), plus the Agent Layer spec in [`../architecture/agent-layer.md`](../architecture/agent-layer.md)) describes a product with seven services, two exposure surfaces ([DMZ](../glossary.md#dmz) for agents, [Canopy](../glossary.md#canopy) for humans), six inspection specialists, a [Gallery](../glossary.md#gallery), a CLI operator surface, and an [LLM gateway](./0007-v1-cost-profile-and-llm-metering.md) — all shipped inside a CloudFormation install. This is the correct v1 shape.

It is not a v0.5 shape. A solo founder building the full v1 before first-customer contact incurs the failure mode named in the [2026-04-24 viability review](../reviews/2026-04-24-viability-review.md) §9: "dies quietly, with a very well-organized `docs/` tree, from lack of a customer."

The question this ADR resolves is what Jungl3 looks like in its *first shipped form* — the artifact the first named design partner installs — as distinct from v1. Without this ADR, every CLAUDE.md §11 open question and every BACKLOG candidate is implicitly sized against v1, and the founder's working queue has no forcing function on scope discipline.

Opens [`CLAUDE.md`](../../CLAUDE.md) §11 #32 (v0.5 scope) by resolving it.

## Decision

v0.5 ships with deliberately reduced scope along four axes. Each reduction is temporary and reversible; each is chosen to shorten the path to first real install by a named design partner.

**1. One exposure surface, not two.** v0.5 ships a single human-accessible surface (the [Canopy](../glossary.md#canopy), in current vocabulary). The [DMZ](../glossary.md#dmz)'s AI-first evaluation role is deferred. Prototypes deploy from the [Jungle](../glossary.md#jungle) directly to the Canopy. [ADR 0011](./0011-canopy-and-ai-first-dmz.md) remains the v1 target; v0.5 defers it.

**2. Two inspection specialists, not six.** v0.5 ships **Environment** (overall install health, service status, deployment state) and **Data** (dataset connectivity, schema, query results). The other four (API, Event, Auth, Listing) are deferred. The `{status, summary, evidence, recommended_action}` response contract from [ADR 0002](./0002-sub-agent-response-contract.md) stands for the two that ship.

**3. P&C claims only, no pack framework.** v0.5 ships one Understory ([ADR 0006](./0006-v1-domain-anchor-insurance-claims.md)'s P&C claims). No [Domain Starter](../glossary.md#domain-starter) selection UI, no pack authoring tooling, no hooks for additional domains. The second domain is a v1 concern.

**4. No Gallery, no CLI polish beyond operator-usability.** v0.5's Canopy surfaces prototypes through whatever minimum mechanism the first design partner's sprint actually requires — most likely a single static listing page, not the full Gallery described in [ADR 0011](./0011-canopy-and-ai-first-dmz.md). The CLI operator console is shipped at the minimum level needed for the founder to operate the install; it is not a selling point.

**What v0.5 keeps at full fidelity.** The [Synthetic Runtime](../glossary.md#synthetic-runtime), the [LLM gateway](./0007-v1-cost-profile-and-llm-metering.md) with budget enforcement, the CloudEvents envelope and dual correlation IDs ([ADR 0005](./0005-event-envelope-and-correlation-identifiers.md)), the hash-chained audit trail ([ADR 0009](./0009-audit-trail-is-append-only-hash-chained.md)), the seven-service decomposition ([ADR 0006](./0006-v1-domain-anchor-insurance-claims.md)), the Seeder and Reaper patterns ([ADR 0010](./0010-seeder-and-reaper-patterns.md)), and the installable-via-Marketplace delivery model ([ADR 0003](./0003-installable-via-aws-marketplace.md)). These are either load-bearing for plausibility (the Synthetic Runtime and audit trail) or structurally expensive to retrofit (the envelope, the gateway, the delivery model).

**Gating condition.** v0.5 is scoped *for* a named design partner. Until [`CLAUDE.md`](../../CLAUDE.md) §11 #21 (first-sponsor context) and the new #31 (design partner acquisition path) show concrete progress, v0.5 is a plan, not a build target. This ADR defines scope; it does not authorize construction in the absence of a pulling customer.

## Consequences

**Enables:**

- A v0.5 scope that one solo engineer can plausibly ship within a quarter, not a year.
- Clear prioritization when [`CLAUDE.md`](../../CLAUDE.md) §11 questions surface: if a question is v0.5-blocking, it resolves now; if it's v1-only, it defers.
- An honest narrative for the first design-partner conversation ("this is v0.5; here's what v1 adds") rather than overpromising against the current docs.
- A forcing function on the first-customer question. v0.5 is defined *for* that customer; with no customer, there is no v0.5.
- A way to re-read the [`BACKLOG.md`](./BACKLOG.md) with a v0.5 filter. Candidates needed for v0.5 rise; v1-only candidates wait.

**Forecloses:**

- A v0.5 that ships the full [ADR 0011](./0011-canopy-and-ai-first-dmz.md) two-surface architecture. If the first design partner needs it at v0.5, this ADR is amended.
- Shipping v0.5 before a first named design partner exists. v0.5 is scoped to a real sprint, not to a speculative one.
- Multi-domain v0.5. A second Understory is a v1 move.
- v0.5 as a public Marketplace listing. v0.5 runs with a named partner; listing publication happens at v1.

**Accepts:**

- v0.5 is architecturally incomplete against the v1 target. Any v0.5 customer (there is one, by construction) gets less than [`../product/positioning.md`](../product/positioning.md) describes. This requires explicit scope communication in design-partner conversations.
- The DMZ/Canopy split is architecturally right but not shippable first. The prompt-injection containment argument in [ADR 0011](./0011-canopy-and-ai-first-dmz.md) context remains valid; v0.5 accepts its risk because v0.5 runs with a named partner whose threat model includes knowing agents are evaluating a prototype built in a sprint, and because there is no public Canopy in v0.5.
- Work authored for v0.5's two specialists has to generalize cleanly to six at v1. Choosing specialists that share response-contract plumbing ([ADR 0002](./0002-sub-agent-response-contract.md)) protects this.
- v0.5 scope is temporary. Each deferred component has a [`BACKLOG.md`](./BACKLOG.md) entry or a v1 ADR pointing here, so "why doesn't v0.5 have X" is answerable by link.
- The public-facing website ([`positioning.md`](../product/positioning.md)) continues to describe v1. v0.5 is a design-partner concept, not a sales concept. Narrowing the public framing to match v0.5 is a separate decision, gated on customer contact (see [`CLAUDE.md`](../../CLAUDE.md) §11 #33).

## Alternatives considered

- **Ship full v1 before first customer.** The currently-implied path. Rejected per [viability review](../reviews/2026-04-24-viability-review.md) §9 — solo founder execution risk is high enough that "ship the full thing" is the path that most often results in nothing shipping.
- **Ship v1 but market it as v0.5.** Rejected as dishonest to the customer and to the founder. Version number is load-bearing here: v0.5 is a different scope commitment, not a different label on the same commitment.
- **Defer first shipped form entirely until v1 is done.** Rejected — [viability review](../reviews/2026-04-24-viability-review.md) §9 names this as the most likely failure mode. v0.5 exists specifically to interrupt it.
- **Ship v0.5 without the LLM gateway, defer [ADR 0007](./0007-v1-cost-profile-and-llm-metering.md) to v1.** Rejected — the gateway is structurally expensive to retrofit ([ADR 0007](./0007-v1-cost-profile-and-llm-metering.md) "Alternatives considered": "Gateway-first is structurally cheaper"). Keep the plumbing, ship fewer specialists on top of it.
- **Ship v0.5 with the DMZ/Canopy split to preserve the [ADR 0011](./0011-canopy-and-ai-first-dmz.md) threat model.** Considered. Rejected for v0.5 because doubled provisioning complexity ([ADR 0011](./0011-canopy-and-ai-first-dmz.md) "Accepts") is the single biggest lifecycle-engineering cost in the accepted architecture, and v0.5's named design partner is a lower-threat context than a multi-tenant public install.
- **Include a third specialist (Event) at v0.5 to cover the Synthetic Runtime's visible behavior.** Considered. Rejected as premature — the Environment specialist can answer "are events flowing?" at install-health granularity; a dedicated Event specialist becomes valuable once a customer asks questions Environment can't answer. Deferred until that feedback arrives.
