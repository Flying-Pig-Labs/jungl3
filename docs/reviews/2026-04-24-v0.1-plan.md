# 2026-04-24 — v0.1 plan

**Frame.** Same-day follow-up to the [viability review](./2026-04-24-viability-review.md) and the [research-sufficiency note](./2026-04-24-research-sufficiency.md). Those argued: research is done, the repo is action-blocked, the #1 unblock is a design-partner conversation. This note writes down the concrete next moves.

## 1. The decision that opens the plan

**v0.1 is a "promotable tiny claims Understory" at todo-app complexity.** Confirmed by the user on 2026-04-24.

"Promotable" means: it follows the eventual Integration Contract, gets registered into a (future) Gallery, goes through the eventual DMZ→Canopy promotion gate. It is *not* a throwaway skeleton — it becomes the permanent smoke-test Understory once the real P&C Understory lands.

"Tiny claims" means: one entity (`Claim`), one three-state workflow (submit → assign → approve/deny), one seeded persona, ~12 seeded records. Claims is the domain overlay on an 80% generic primitive. **No maker-checker, no LLM, no DMZ agents, no Gallery** in v0.1 — those are explicitly deferred.

The reasoning (three competing pressures, resolved):

- **"Todo app" instinct** — proves the mechanics without domain distraction. Right pressure.
- **"Tiny claims ecosystem" instinct** — avoids the throwaway moment; gives something credible to show in a design-partner call. Right for a different reason.
- **[ADR 0006](../decisions/0006-v1-domain-anchor-insurance-claims.md) and [ADR 0012](../decisions/0012-v0.5-wedge-scope.md) already pin P&C claims as the v1 domain.** Skipping it in v0.1 creates an odd gap.

Resolution: *primitives* are domain-neutral (Control Plane vends, Understory comes up alive, Integration Contract honored, install+teardown work); the *domain* is the thinnest possible overlay. If a real customer turns out not to be P&C, the primitives survive; only the overlay changes.

## 2. What v0.1 proves (and what it does not)

**Proves:**

1. **Vend flow.** Control Plane creates a new Jungle on demand. Stack comes up. URL is reachable.
2. **Understory is alive on day one.** When a user opens that URL, there is already data. Not an empty form.
3. **Teardown flow.** Reaper destroys the Jungle cleanly. No orphaned resources. No data left behind.
4. **Install-time seeding is deterministic.** Every vend produces the same seed state (per the [ADR 0010](../decisions/0010-seeder-and-reaper-patterns.md) + [`findings.md §6`](../research/findings.md) pattern).
5. **Integration Contract has a concrete first shape.** A prototype built on the Understory can say "I exist" in a machine-readable way. Single field at first; grows later.
6. **Observability.** Single CloudWatch Log group per install, structured JSON, `trace_id` + `install_id` on every line ([ADR 0005](../decisions/0005-event-envelope-and-correlation-identifiers.md) in spirit — logs now, full events later).

**Does NOT prove (deliberately):**

- Maker-checker ([§11 #16](../../CLAUDE.md)).
- LLM cost discipline ([§11 #18](../../CLAUDE.md)).
- DMZ agent probing.
- Canopy / Gallery / Inspection surfaces.
- Marketplace listing submission.
- Upgrade/update safety ([§11 #3](../../CLAUDE.md) — the genuinely hard problem; untouched by v0.1 on purpose).

Honest gap: v0.1 does not prove Jungl3 works; it proves the *scaffolding* works. v0.5 (per [ADR 0012](../decisions/0012-v0.5-wedge-scope.md)) is where the product thesis gets tested.

## 3. Concrete shape

| Subdir | What lives there in v0.1 | Notes |
| --- | --- | --- |
| `marketplace-listing/` | Empty scaffold + `README.md` documenting intent. | No CFN template yet. v0.1 installs via `cdk deploy` / `aws cloudformation deploy` from the local machine. Marketplace packaging is v0.5/v1. |
| `control-plane/` | `vend` Lambda + `reap` Lambda + a small CLI wrapper. Vend params: `install_id`, `team_name`. Creates a nested stack containing one Understory. | Written in TypeScript. CFN or CDK per Track B2 outcome. |
| `control-plane/understories/claims/` | DynamoDB table (`Claim`), Lambda-backed API (POST/GET/PATCH), static HTML+JS page, seed script (~12 records). | **Complexity budget: ≤400 LOC total.** If I overshoot, I'm overbuilding. Vanilla HTML + fetch. No framework. |
| `contracts/` | `integration-contract.v0.ts` — single type, single field (`prototype_id`). Grows with use. | No framework; pure TypeScript types. |

**Deferred repo-policy question:** `CLAUDE.md §4` doesn't list `understories/` as a top-level subdir. Options are (1) put it inside `control-plane/understories/claims/` (couples Understories to Control Plane — what v0.1 does for now), (2) make `understories/` a top-level subdir when a second Understory appears. **v0.1 picks (1). Revisit when the second Understory exists, and decide via an ADR then.**

**Cost expectation** `[Inference]`: whole stack 24/7 ≪ $5/install/month. Single-digit Lambda invocations, tiny DynamoDB On-Demand, no NAT, no ALB. If actual cost surprises upward, that's early empirical data on [§11 #18](../../CLAUDE.md).

## 4. The plan — three parallel tracks

### Track A — Design-partner outreach (starts now, runs forever)

Named steps, not vague "reach out."

- [ ] **A1.** List 5 named P&C innovation-lead targets. Not "Chubb innovation team" — a human name at Chubb.
- [ ] **A2.** For each, identify the warm-intro path. Prioritize warm; mark cold-outreach separately.
- [ ] **A3.** Draft outreach template: 4 sentences, asks for 30 minutes, frames Jungl3 as "an AI-native prototype foundry we're scoping against P&C claims innovation." No decks, no `docs/` links.
- [ ] **A4.** Send three intros this week, two next week.
- [ ] **A5.** When a call gets booked: stop Track C, prep for the call. When the call happens: let its output rewrite priorities.

### Track B — Architecture-hardening (half-day passes, interleaved with C)

No new research. Decision-closing passes on inputs the repo already has.

- [ ] **B1.** Pin MVR floor ([§11 #17](../../CLAUDE.md)). Half-day ADR. Inputs: [`findings.md §5.5`](../research/findings.md), archived [`research1-aws-installable-shape.md`](../research-archive/first-generation/research1-aws-installable-shape.md), archived [`aws-innovation-environment-design-report.md`](../research-archive/user-memos-2026-04-24/aws-innovation-environment-design-report.md). Produces ADR 0013 `[Unverified numbering]`.
- [ ] **B2.** Pick IaC authoring tool ([§11 #7](../../CLAUDE.md)). One-day exercise: write the vend-a-Jungle flow in CDK and in raw CFN. Pick. Produces ADR 0014 `[Unverified numbering]`.
- [ ] **B3.** Pin Control Plane runtime ([§11 #11](../../CLAUDE.md)). Lambda vs Fargate. The v0.1 vend Lambda in Track C is itself the test — if Lambda handles vend/reap in <30s, Lambda wins for v0.1 (with explicit "revisit at v1"). Produces ADR 0015 `[Unverified numbering]`.
- [ ] **B4.** LLM cost-estimate empirical study ([§11 #18](../../CLAUDE.md)). ~5 representative agent tasks, log tokens, compare to [ADR 0007](../decisions/0007-v1-cost-profile-and-llm-metering.md). Desk work. Updates the ADR's accuracy assumption.

### Track C — v0.1 skeleton build

Target: vendable + reapable claims Understory running in the dev AWS account, proving the 6 primitives in §2.

- [x] **C0.** AWS MCP servers installed and enabled (`aws-docs`, `aws-api` with `READ_OPERATIONS_ONLY=true`). Confirmed 2026-04-24.
- [ ] **C1.** Create `control-plane/` with `README.md` + dependency manifest. TypeScript. If **B2** not yet done, default to raw CloudFormation (CDK compiles to CFN anyway; safe to migrate later).
- [ ] **C2.** Write the vend Lambda: takes `install_id` + `team_name`, creates a nested stack containing the claims Understory.
- [ ] **C3.** Write the reap Lambda: destroys the nested stack, verifies no orphaned resources.
- [ ] **C4.** Create `control-plane/understories/claims/`: DynamoDB table, API Lambda, static page, seed script. Budget: ≤400 LOC.
- [ ] **C5.** Create `contracts/integration-contract.v0.ts`. One type, one field.
- [ ] **C6.** Structured JSON logging with `install_id` + `trace_id` on every line.
- [ ] **C7.** Vend one install by hand. Open the URL. Create a claim. See it persist. Tear it down. Verify cleanup.
- [ ] **C8.** Run vend/reap three times back-to-back. Same deterministic seed each time. Nothing leaks.
- [ ] **C9.** `control-plane/RUNBOOK.md` — 1 page: how to vend/reap, how to inspect logs, how to diagnose a stuck stack.

## 5. Execution order

**C0 is done.** Start with **B2** (pick IaC tool) because it unblocks most of Track C, *or* start **C1** using raw CloudFormation as default and let **B2** rule later. My preference: the latter — lowest-commitment starting point; CFN is portable into CDK later if B2 picks CDK.

Track A runs mostly in the user's hands, not the agent's. The agent can draft **A3** (outreach template) when asked; **A1/A2/A4** are human.

## 6. Stop-the-world triggers

- **A design-partner call gets booked** → pause Track C at next natural boundary, move to call prep.
- **Cost surprises upward in Track C** (install > $20/install/month) → pause, investigate, update [§11 #18](../../CLAUDE.md) with empirical data.
- **Vend or reap takes > 5 minutes** → pause, reconsider [§11 #11](../../CLAUDE.md) (Lambda vs Fargate) and [§11 #3](../../CLAUDE.md) (upgrade strategy).
- **`aws-api` MCP read-only mode blocks something legitimate** → fix config per-session, do not disable globally.

## 7. Explicit non-goals for v0.1

Call these out so they can't sneak back in:

- Marketplace submission.
- Any DMZ or Canopy code.
- Any LLM integration.
- Any maker-checker logic.
- Any attempt at upgrade-safety.
- Any multi-account or cross-install capability.
- Any auth beyond "the API endpoint is public and `install_id` is the security boundary." Unacceptable for production; fine for a dev-account smoke test of 10-minute-lifetime installs.
