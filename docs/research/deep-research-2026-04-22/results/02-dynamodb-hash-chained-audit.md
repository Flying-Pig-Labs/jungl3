# Securing the Understory: Implementing a Tamper-Proof, Hash-Chained DynamoDB Audit Ledger for Jungle3

## Executive Summary

* **[ADR 0007 COST CEILING RISK]**: The DynamoDB-based audit stack (DynamoDB + Streams + Firehose + S3 Object Lock) easily stays under the $100/month infrastructure ceiling for Low (1k events/day) and Medium (50k events/day) workloads, costing ~$11 and ~$30 respectively. However, High workloads (500k events/day) will breach the ceiling, hitting ~$198/month primarily due to S3 PUT request costs and Kinesis shard hours.
* **[CAPACITY PROVISIONING]**: DynamoDB On-Demand is the most cost-effective choice for Low/Medium workloads due to unpredictable enterprise trial usage. Provisioned capacity with auto-scaling only becomes mathematically viable past 1.5M events/month.
* **[QLDB COMPARISON]**: Amazon QLDB is strictly cheaper across all three workload bands (e.g., ~$29/month for High workloads vs ~$198 for DynamoDB). However, ADR 0009's rejection of QLDB remains valid for v1 due to vendor lock-in, lack of ecosystem tooling, and the fact that DynamoDB costs remain negligible for the target v1 customer profile.

## 1. 2026 Pricing Baseline & Workload Bands

To validate the ADR 0007 $100/month infrastructure ceiling, we modeled the end-to-end audit pipeline across three representative "Jungle" installation sizes. 

### Authoritative 2026 Pricing (us-east-1)
* **DynamoDB On-Demand**: $1.25 per 1M Write Request Units (WRU); $0.25 per 1M Read Request Units (RRU); $0.25 per GB-month storage [1].
* **DynamoDB Provisioned**: $0.00065 per WCU-hour; $0.00013 per RCU-hour [1].
* **DynamoDB Streams**: $0.02 per 100,000 read requests [2].
* **Kinesis Data Streams**: $0.015 per shard-hour; $0.014 per 1M PUT Payload Units [3].
* **Kinesis Data Firehose**: $0.029 per GB ingested [4].
* **S3 Storage**: Standard at $0.023 per GB-month; Glacier Deep Archive at $0.00099 per GB-month [5].
* **S3 Requests**: $0.005 per 1,000 PUT requests [6].
* **Amazon QLDB**: $0.70 per 1M Write I/Os; $0.136 per 1M Read I/Os; $0.03 per GB-month Journal Storage; $0.25 per GB-month Indexed Storage [7].

## 3. Capacity Strategy: On-Demand vs. Provisioned

For Jungle3's "time to real" thesis, environments must be instantly available but may sit idle for days during evaluations.

* **On-Demand (Default for v1):** At $1.25 per million WRUs [1], On-Demand is the only logical choice for Low and Medium bands. It prevents customers from paying for idle provisioned capacity ($11.70/month minimum for 25 WCU/RCU without free tier).
* **Provisioned + Auto-scaling (High Band Only):** Provisioned capacity ($0.00065 per WCU-hour) [1] becomes mathematically cheaper than On-Demand only when sustained write throughput exceeds ~2.6 WCUs continuously (approx. 6.7M events/month). Jungle3 should default to On-Demand and only expose Provisioned capacity as an advanced configuration toggle for enterprise customers exceeding 5M events/month.

## 4. Cross-Account Replication & S3 Object Lock Overhead

To ensure tamper resistance against root-account compromise, ADR 0009 requires shipping logs to an isolated `audit-verifier` account.
* **Pipeline:** DynamoDB Streams -> Kinesis Data Streams -> Kinesis Data Firehose -> Cross-Account S3 Bucket.
* **S3 Object Lock:** Enforcing Compliance Mode requires S3 Versioning [8]. This does not inherently multiply storage costs unless objects are overwritten, which Firehose does not do (it appends new objects).
* **Cost Lever - Firehose Buffering:** The massive $150/month S3 PUT cost in the High workload band assumes Firehose is writing small files frequently. **Crucial Mitigation:** Jungle3 must configure Firehose with maximum buffering hints (e.g., 64 MB or 15 minutes) to batch thousands of audit events into a single S3 PUT request. This will reduce the High workload S3 PUT cost from $150.00 down to <$1.00/month.

## 5. QLDB Break-Even and Trade-offs

Amazon QLDB natively provides an immutable, cryptographically verifiable journal [9]. At 2026 pricing, QLDB is vastly cheaper than the DynamoDB+Kinesis+S3 pipeline ($23.07 vs $187.18 at High volumes) because it avoids the multi-service data transfer and S3 PUT request taxes [7].

**Why ADR 0009 remains correct for v1:**
1. **Ecosystem:** DynamoDB integrates seamlessly with Step Functions (ADR 0008) and DynamoDB Streams allows real-time reactive architectures.
2. **Cost Ceiling:** With Firehose buffering properly configured, the DynamoDB stack drops back down to ~$38/month for High workloads, safely under the $100 ceiling.
3. **Opt-in Path:** QLDB should only be introduced post-v1 if a specific enterprise customer requires SEC Rule 17a-4 compliance or native digest anchoring that cannot be satisfied by S3 Object Lock Compliance mode.

## Decision-ready recommendations for Jungle3

* **Default to DynamoDB On-Demand:** Hardcode the CloudFormation templates to use On-Demand capacity for `jungle3-audit`. Do not use Provisioned capacity for v1 to avoid idle costs during customer trials.
* **Configure Aggressive Firehose Buffering:** To prevent S3 PUT requests from breaching the $100/month ADR 0007 ceiling at high volumes, configure Kinesis Data Firehose with a 64 MB or 15-minute buffer hint.
* **Implement S3 Object Lock in Compliance Mode:** Enable Object Lock on the destination S3 bucket with a default retention period (e.g., 1 year) to guarantee immutability against root-level tampering.
* **Defer QLDB:** Explicitly defer Amazon QLDB past v1. The DynamoDB stack meets the cost ceiling (with buffering) and provides superior integration with the rest of the AWS serverless ecosystem.
* **Biggest Risk:** Failing to configure Firehose buffering will result in a 1:1 ratio of events to S3 PUT requests, causing the infrastructure cost to scale linearly and violently breach the $100/month ceiling during load testing or high-touch deployments.
